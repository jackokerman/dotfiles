# Styling Tool Choice

- Follow the repository's established styling system.
- For a new owned frontend app, use plain CSS for a tiny or mostly static UI. Prefer a type-safe, build-integrated system once repeated tokens, variants, or shared style primitives justify it.
- Choose a framework-compatible tool; do not force a React-oriented package onto Svelte or another framework.
- Do not add a component framework by default. Adopt one when its accessible primitives or component breadth justify its conventions and dependency surface.
- Document contributor setup, code generation, and ignored generated artifacts.
